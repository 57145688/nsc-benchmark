# 从 NuScale-like SMR 基准到仿星器：工作总结与可复用经验

本文分两部分：先交代 `nsc-benchmark` 这个仓库实际做成了什么，再把这些做法映射到仿星器（stellarator）的仿真与设计上，指出哪些能直接搬、哪些必须换掉。

## 1. 这个仓库做成了什么

一条从参数到可视化的闭环，全部可重跑：

```
params/nuscale_core.json
   ├─ CadQuery → pin / assembly / core / module 四级 STEP+STL → Plotly HTML → Blender 渲染
   ├─ OpenMC 0.16 → 37 组件 2D 堆芯 → k_eff、组件/ pin 功率、能谱、核素反应率
   ├─ OpenFOAM v1912 → 5° 轴对称自然循环 → 温度场、速度场、环带密度
   ├─ couple.py → 水密度反馈迭代（OpenMC ↔ OpenFOAM）
   └─ make_figures / make_core_figures / make_gallery → results/figures/index.html
```

关键量化结果：

| 项目 | 结果 |
|---|---|
| 堆芯 | 37 组 17×17 组件，活性段 200 cm，RPV 内径 122.6 cm |
| 冷态 / 热态 k_eff | 1.25552 ± 0.00102 → 1.22378 ± 0.00097 |
| 径向功率峰值 | 组件 1.29×，组件内 pin 1.24× |
| 能谱 | 热中子 16.3%，快中子 45.5%，U-235 贡献 94.6% 裂变 |
| 自然循环 | 堆芯 +0.245 m/s，下降段 −0.344 m/s，温度 521–620 K |
| SG 换热器 | 2.210 MW vs 堆芯 2.222 MW，不平衡 0.53% |
| 压降标定 | 40 kPa @ 4 m/s（棒束），按 3.05 倍流通面积比折算 |

代码分工：`nsc_bench/cad.py`、`nsc_bench/core.py` 是模型层；`scripts/` 下每个可执行步骤一个脚本；`results/` 只放小体积 JSON 摘要与图，原始场/状态点不进 git。

## 2. 与堆型无关、可以直接复用的做法

1. **单一参数源。** 几何、材料、富集度、热工设计点只有一份 JSON，CAD 与两个求解器都从它读。改一处，全链路同时变。
2. **按求解器分 LOD。** 单棒、组件、堆芯、模块四级；中子学用 pin-by-pin，CFD 用多孔等效；不为 CFD 去建 289 根棒的实体。
3. **每个环节可单独重跑。** `build → run → post → figure` 四段式，任一步失败不必从头来。
4. **结果写成有 schema 的 JSON，而不是只留日志。** 下游出图只读 JSON，图注数字自动生成，避免文档与数据脱节。
5. **守恒量做自检。** 中子学看 k 收敛与裂变率份额，热工看 SG 热负荷对堆芯功率（0.53%），CFD 看质量/能量平衡；守恒对不上就是模型错了。
6. **统计误差显式记录。** 每次 run 存 `k_sigma`、粒子数、批数、非活跃批数；出图时用它判断能不能下结论。
7. **环境隔离。** Windows 上写代码、WSL 里跑 OpenMC/OpenFOAM；含空格的路径先复制到 `$HOME` 再算。
8. **可视化流水线化。** matplotlib 出物理图，Blender 出几何渲染，一个 HTML 图集汇总；全部由脚本生成。

## 3. 裂变 SMR 与仿星器的关键差异（这些经验不能直接搬）

| 维度 | 本项目（裂变 SMR） | 仿星器 |
|---|---|---|
| 对称性 | 2D 轴对称 / 1/72 wedge | **无轴对称**，只能用 field-period 对称（1/N） |
| 几何 | 圆柱 + 方阵，CSG 即可 | 三维扭曲线圈与等离子体边界，必须 CAD→DAGMC |
| 中子源 | 裂变谱（~2 MeV） | D-T 14 MeV，需氚增殖、屏蔽、dpa |
| 热源 | 燃料棒体积热源 | 中子壁负载 + 辐射热流，偏滤器局部极高热流 |
| 冷却剂 | 单相水自然循环 | 液态金属 / 氦 / 水包层，液态金属有 MHD 压降 |
| 物理前置 | 无 | **必须先有磁面平衡**（VMEC/DESC）才能谈输运与热工 |
| 计算量 | 分钟级 | 小时级，必须并行 + 代理模型 |

一句话：本项目的 CAD/CAE 接口规范、参数管理、收敛与自检习惯可以照搬；**几何、中子源、热源、对称性和物理前置全部要重做**。

## 4. 仿星器仿真与设计的建议路线

### 阶段 0：参数与几何（最先做，也最容易返工）

- 用 SIMSOPT 之类的框架把线圈电流、线圈形状、等离子体边界参数化，**先固定一套参数 spine**（建议 YAML，附单位与坐标系约定）。
- 场线追踪 / Poincaré 图先跑通，确认磁面存在、无大岛，再去建 CAD。
- CAD 从参数化曲面导出 STEP，再用 `cad_to_dagmc` 转 DAGMC，别手工建实体。
- 线圈与真空室、包层之间留装配间隙检查（本项目的 CAD 体积/干涉校验可以直接复用）。

### 阶段 1：平衡与磁面

- VMEC/DESC 求有限 β 平衡，输出 iota、磁剪切、磁井、B·n 误差。
- 线圈优化目标写清楚：准对称性、曲率、工程约束（力、电流密度、间隙）。
- 这一阶段的输出是后续所有 CAE 的输入，必须版本化：平衡文件 + 线圈文件 + 参数 hash 一起存。

### 阶段 2：中子学

- OpenMC + DAGMC 做 3D 中子学，源用等离子体中子源分布（不是点源）。
- 关注量：TBR、屏蔽剂量、结构 dpa、真空室活化；网格 tally 用 field-period 对称降低方差。
- 几何简化要记录：线圈可以等效为均质化导体，但包层/第一壁不行。
- 统计量级参照本项目：5k 粒子时组件级功率噪声约 20%，20k 才降到约 5%；3D 只会更贵，先算方差再定粒子数。

### 阶段 3：热工与水力学

- 包层/第一壁/偏滤器三个区域分开建模；偏滤器热流用单独的高分辨率模型。
- 液态金属包层必须考虑 MHD 压降与传热，普通 k-ε 不够；氦冷则关注换热系数与压损。
- 不要沿用本项目的自然循环回路假设：仿星器一次侧是强制循环。

### 阶段 4：耦合与不确定性

- 先做稳态：中子壁负载 → 热工温度 → 材料截面/密度反馈（弱耦合足够）。
- 再做瞬态：失流、失冷；本项目证明瞬态里出现周期性振荡不一定是发散，要先做能量平衡诊断。
- 用代理模型（GP/神经网络）替代部分 3D 中子学或 CFD 调用，否则耦合迭代不可行。

## 5. 建模与工程规范 checklist

- [ ] 一份参数源，单位与坐标系写在文件头。
- [ ] 每个求解器只吃自己需要的 LOD，接口用文件而不是内存对象。
- [ ] 每次 run 记录：参数 hash、代码版本、粒子数/网格数、收敛判据。
- [ ] 结果 JSON 有固定 schema，图注数字从 JSON 生成。
- [ ] 守恒量自检（能量、质量、k 收敛、TBR 与裂变率的量级）。
- [ ] 几何简化清单：简化了什么、为什么、影响哪个量。
- [ ] 原始场/状态点不进 git，只留小摘要与可再生配置。

## 6. 这个项目踩过的坑（仿星器同样会遇到）

1. **路径含空格。** OpenFOAM 直接拒绝；先复制到无空格路径再算。
2. **后处理读到旧结果。** 时间目录按字符串排序、旧目录残留都会让"最新"取错；复制回来时先清空。
3. **统计不足就画图。** 5k 粒子的 7×7 功率图看似有物理结构，其实是噪声。
4. **参数表重复/遗漏。** 富集度列表里 `[6,3]` 出现两次、`[7,3]` 缺失，导致一个组件静默用兜底材料；参数表要做唯一性与完备性校验。
5. **物性系数拍脑袋。** 热膨胀系数低估 7 倍、水密度用二次拟合偏差 20%，都会让结论完全变样；用 IAPWS 这类标准表。
6. **几何布局造成倒流。** 把换热器放在堆芯正上方会让冷流体重力塌陷；拓扑先做量级判断再算。
7. **边界条件不自然。** 固定体积热阱会让温度场过冷/过热，换成随温度变化的换热器后才自洽。
8. **重启逻辑静默失效。** 先删工作目录再备份字段，会导致每次"续算"其实从初场开始；续算后必须对比 t=0 场。
9. **渲染限制。** STL 合并实体无法分件赋材质；需要分色时按连通域拆分。
10. **文档与数据脱节。** 手动抄数字必然过期；让图注从 JSON 读。

## 7. 如果明天开始做仿星器，第一周的顺序

1. 定参数 spine（线圈、边界、场周期数、β、功率）。
2. 跑通场线追踪与 Poincaré 图。
3. 用 SIMSOPT 做一轮线圈优化，存平衡 + 线圈。
4. 导出 STEP → DAGMC，跑一个只有第一壁和真空室的 OpenMC 计数率算例，确认几何与源。
5. 建一个最简包层热工模型，做能量守恒自检。
6. 把这三步接成脚本流水线，并生成一页图集。

先保证"几何—中子—热工"三段能各自独立跑通，再谈耦合；这和自己这个仓库从 CAD 到耦合的推进顺序是一致的。
